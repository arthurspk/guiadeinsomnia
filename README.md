## :dart: O guia para alavancar a sua carreira

> Insomnia é o cliente de API gratuito e open source mantido pela Kong: uma alternativa direta ao Postman para testar e organizar chamadas REST, GraphQL, gRPC, WebSocket e SSE, com foco em guardar seus dados localmente (ou em Git) em vez de depender de nuvem. Nasceu em 2016, hoje soma quase 40 mil estrelas no GitHub e é usado por quem valoriza um cliente leve, com sincronização via Git, geração de mock servers, testes automatizados via CLI (`inso`) e, mais recentemente, recursos de IA embutidos — geração de mocks a partir de prompt e suporte a servidores MCP. Este guia reúne documentação oficial, tutoriais práticos, ferramentas do ecossistema, projetos para praticar, comunidades e um capítulo específico sobre IA no dia a dia com o Insomnia — tudo verificado, para quem está criando a primeira requisição ou já mantém coleções inteiras sincronizadas via Git.

## 🗺️ Roadmap

- [roadmap.sh — API Design Roadmap](https://roadmap.sh/api-design) — Roadmap visual e interativo da comunidade sobre design e boas práticas de API; a base conceitual do que você organiza e testa no Insomnia.
- [roadmap.sh — Backend Roadmap](https://roadmap.sh/backend) — Roadmap completo de back-end; mostra onde um cliente de API como o Insomnia entra no fluxo de trabalho de quem desenvolve.

**Trilha resumida** (siga na ordem; cada etapa tem recursos nas seções abaixo):

1. **Fundamentos de API e HTTP** — métodos (`GET`, `POST`, `PUT`, `DELETE`), status codes, headers, JSON.
2. **Instale o Insomnia** e faça sua primeira requisição a uma API pública.
3. **Coleções e ambientes** — organize requisições, use variáveis de ambiente para não repetir valores fixos.
4. **Autenticação** — API Key, Bearer Token, OAuth 2.0: como configurar em cada requisição.
5. **Variáveis dinâmicas e template tags** — gere dados de teste (UUID, timestamps, valores aleatórios) sem sair do Insomnia.
6. **Scripts e testes** — escreva scripts pré/pós-requisição e testes automatizados para validar respostas.
7. **Git Sync** — versione coleções e ambientes num repositório Git, sozinho ou em equipe.
8. **Automação via CLI** — use o `inso` para rodar coleções e testes direto do terminal e em pipelines de CI/CD.
9. **Mock servers e Design mode** — simule respostas antes da API existir e trabalhe com especificações OpenAPI dentro do próprio Insomnia.
10. **IA na prática** — use os recursos de IA do Insomnia para gerar mock servers a partir de um prompt e conectar servidores MCP.

## 🤖 IA na prática

A partir da versão 12, o Insomnia passou a ter recursos de IA nativos — não é só "usar o ChatGPT do lado", a própria ferramenta ganhou funcionalidades específicas.

- **Geração de mock servers por prompt**: em vez de montar rotas e respostas manualmente, você descreve o que precisa (ou aponta uma spec OpenAPI, ou uma URL real) e o Insomnia monta o mock server sozinho. Veja a [documentação oficial de IA no Insomnia](https://developer.konghq.com/insomnia/ai-in-insomnia/) para os detalhes de configuração.
- **Sugestão de commits com IA**: ao usar o Git Sync, o Insomnia analisa as mudanças em stage e sugere agrupamentos lógicos e mensagens de commit — útil para manter um histórico organizado quando várias pessoas editam as mesmas coleções.
- **Insomnia como cliente MCP**: o Insomnia conecta a servidores [Model Context Protocol](https://developer.konghq.com/insomnia/mcp-clients-in-insomnia/), permitindo descobrir, testar e invocar ferramentas expostas por esses servidores diretamente na interface — útil para quem está construindo ou depurando integrações com agentes de IA. Veja o [tutorial oficial de como testar ferramentas MCP agregadas no Insomnia](https://developer.konghq.com/how-to/use-insomnia-mcp-clients-to-test-aggregated-mcp-tools/) para um passo a passo prático.

**Para configurar**: em `Preferences > AI Settings`, escolha um provedor (Claude, OpenAI, Gemini, uma URL de LLM própria ou um modelo local) e ative os recursos de IA no painel correspondente.

**Limites e boas práticas**
- Segundo a documentação oficial, os recursos de IA são gratuitos "a partir do Insomnia v12", mas isso pode mudar em versões futuras — confira a página oficial antes de depender deles em produção.
- Credenciais de provedores de IA ficam armazenadas localmente e não são sincronizadas entre contas ou dispositivos — ainda assim, evite colar segredos de produção em prompts sem revisar a política de segurança da sua empresa.
- Modelos locais com menos de 10 bilhões de parâmetros tendem a gerar sugestões de commit menos precisas, segundo a própria documentação da Kong.
- Sempre revise um mock server gerado por IA antes de usá-lo como referência de contrato de API: campos ou endpoints inventados pela IA não substituem a especificação real.
